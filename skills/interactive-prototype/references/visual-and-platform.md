# 视觉与平台适配

## 高保真的来源

高保真不等于装饰丰富。原型的可信度来自四层一致：

1. **对象一致**：页面展示用户真实关心的内容，不用无意义卡片填满。
2. **状态一致**：控件、内容和结果随操作同步变化。
3. **平台一致**：信息密度、导航、点击区域和输入方式符合使用设备。
4. **视觉一致**：字体、间距、颜色、形状和动效服务同一产品气质。

先继承用户提供的设计系统、品牌资产、代码组件和真实内容。若没有，从核心对象寻找视觉隐喻，例如时间产品可以围绕时间轴，票据产品围绕纸张和归档，空间产品围绕地图和距离。不要从“科技感”“高级感”这类形容词直接套模板。

## 移动端

- 默认设计画布为 390 × 844 CSS 像素，并在电脑浏览器的手机窗口中展示。
- 主要动作放在拇指容易到达的位置；点击区域建议至少 44 × 44。
- 尊重顶部和底部安全区域，内容不能被状态区域或底部指示器遮挡。
- 一屏只保留当前任务需要的层级。底部导航适合少量并列一级目的地，不用于主任务内部每一步。
- 键盘出现、长内容滚动、弹层关闭和返回后的状态都要考虑。
- 设备外框属于演示层；产品页面本身仍应能在 `prototype.html` 中独立打开。

## 桌面端

- 默认预览使用 1440 × 900，允许根据产品调整。
- 利用更宽空间呈现上下文、批量操作和多列关系，不把手机卡片简单横向铺开。
- 为键盘、鼠标悬停、右键或快捷键设计时，必须同时提供可发现的界面入口。
- 数据表格、侧栏、画布和属性面板需要清楚的宽度策略、溢出行为和空状态。
- 在浏览器窗口中展示地址栏或标题栏，帮助用户理解这是一件可操作的软件，而不是海报。

## 同时支持移动与桌面

`responsive` 不是等比缩放。同一核心任务需要分别决定：

- 哪些内容始终优先；
- 哪些信息在手机折叠、在桌面常驻；
- 导航如何从底栏变为侧栏或顶部导航；
- 鼠标悬停信息如何在触摸设备上被发现；
- 对话框、抽屉和全屏页面如何随空间改变。

至少在 390 × 844 和 1440 × 900 两个尺寸验收。

## 视觉研究和许可

研究参考时记录具体页面、作者、访问日期、借鉴的方法和许可判断。可以借鉴层级、节奏、状态反馈和通用模式；不要复制第三方的插画、图标、商标、独特版式或完整界面。没有明确许可的素材只用于研究，不进入交付文件。

真实品牌出现时优先使用用户提供或官方允许使用的资产。下载素材到本地相对路径并保留来源记录，避免浏览器预览依赖临时远程链接。

## 反模板检查

交付前逐项问：

- 去掉产品名后，界面还能通过对象、文案和行为被认出来吗？
- 每张卡片是否承担实际信息或操作作用？
- 装饰图标、标签、渐变和阴影是否在解释层级？
- 是否有一个与产品机制直接相关、值得记住的视觉细节？
- 视觉是否掩盖了主任务或造成错误的点击暗示？

## 可访问性与动效

- 文本与背景保持可读对比度，不只靠颜色传达状态。
- 图标按钮有 `aria-label`，表单控件有可见标签或程序化名称。
- 焦点顺序与视觉顺序一致，焦点样式清楚。
- 动效表达状态变化，持续时间克制；支持 `prefers-reduced-motion`。
- 自动播放、循环和视差不是默认选项。原型的首要目标是帮助用户理解和完成任务。
