# 视觉研究与质量门槛

## 参考来源

按用途选择作者或官方页：Mobbin、Refero、App Store 与产品官网用于真实流程；Behance、Figma Community、Penpot 用于完整案例；Dribbble、Awwwards、Codrops 用于局部表达；Fonts In Use、Brand New、BP&O 用于字体与品牌；Apple HIG 用于平台规则。

每项记录标题、作者或所有者、原始链接、访问日期、采用的方法、概念或实物属性与许可判断。公开可见不等于允许复用。无明确许可的素材只提炼通用方法，不进入成品。

## 三方向门槛

正式制作前至少提出三套在结构上不同的方向，不能只是换色：

- 一套以核心对象的结构或材质为主。
- 一套以核心动作或状态变化为主。
- 一套以信息关系、时间或空间模型为主。

每套写清主构图、页面节奏、产品隐喻、与最近 7 期的差异、潜在同质化风险。选择标准依次是：核心行为可读、产品特异、信息层级、系列延展、视觉新鲜度。

## 从行为抽象

完成 3–5 组：

`来源线索或操作痕迹 → 设计原语 → 界面组件或状态 → 产品作用`

主要原语至少复用于两类组件。视觉应来自产品正在处理的对象、动作、时间变化或信息关系。与任务无关的海报风格、装饰符号、玻璃拟态、卡片堆叠或渐变删除。

## 先核心 UI 后传播图

先完成核心一屏、主操作前状态和操作后状态。核心 UI 必须回答：

- 用户现在看什么？
- 此刻唯一主操作是什么？
- 操作后什么值、位置或状态改变？
- 出错、中断或返回时如何恢复？

只有这三张成立后才制作封面、视觉推导和场景页。手机模型不能成为产品设计的替代物；若拿掉标题和说明，核心页面仍应让人看懂主要任务。

## 模板指纹

每期记录：

- `layout`：页面网格与图文位置。
- `hero_structure`：第一视觉是界面、物件、人物、数据还是环境。
- `palette`：主辅色关系与明暗。
- `type_treatment`：字号对比、字体气质与文本密度。
- `device_treatment`：手机是否出现、角度、比例与裁切。

与最近 7 期比较。颜色变化不构成新模板。若仍是“纯色或米色底、居中手机、大标题、圆角信息卡、荧光点缀”的相同骨架，必须重选构图。

## 两轮目视复核

### 联系表

检查 5–7 张缩略图：是否连续复用同一构图、是否只有文案不同、产品机制是否至少出现三次、轻重节奏是否有变化、第一二张是否讲清问题/动作/结果。

### 100% 与核心屏

逐张查看中文、数字、日期、字体、图标、边距、对齐、裁切和设备一致性。重点查看核心屏是否像能操作的产品，而非海报；状态变化是否使用同一对象和控件；没有第三方 Logo 或不可授权素材。

六项评分均须 8–10：产品特异性、信息层级、核心 UI 可信度、序列变化、可读性、完成度。任何一项低于 8，重做最弱的页面后重新评分。评分是复核记录，不是自动证明；明显问题存在时不得填高分通过。
