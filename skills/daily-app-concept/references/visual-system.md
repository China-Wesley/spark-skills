# 视觉研究与产品抽象

## 研究渠道

按用途选择来源，优先作者或官方项目页：

- 真实移动产品流程：[Mobbin](https://mobbin.com/)、[Refero](https://refero.design/)、App Store 与产品官网。
- 完整设计案例：[Behance](https://www.behance.net/)、[Figma Community](https://www.figma.com/community)、[Penpot Hub](https://penpot.app/libraries-templates.html)。
- 视觉亮点与探索：[Dribbble](https://dribbble.com/)、[Awwwards](https://www.awwwards.com/)、[Codrops](https://tympanus.net/codrops/)。
- 品牌、字体与配色：[Brand New](https://www.underconsideration.com/brandnew/)、[BP&O](https://bpando.org/)、[Fonts In Use](https://fontsinuse.com/)、[Happy Hues](https://www.happyhues.co/)。
- 动效与状态：[Rive](https://rive.app/community/)、[LottieFiles](https://lottiefiles.com/)。
- 平台规则与原生组件：[Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/)。

不同来源承担不同证据作用。Dribbble 的单屏效果不能证明完整流程，Behance 的概念项目不能当作已上线产品，公开可见也不等于允许复用。

每个参考记录：标题、作者、原始链接、发布时间或访问日期、借鉴的方法、是否为概念作品、许可判断。没有明确授权的素材不进入正式图片。

## 案例拆解

从以下角度提炼通用方法：

- 第一眼是否能看懂产品对象和主要任务。
- 信息层级是否支持核心动作。
- 状态变化是否足够明显，错误是否可恢复。
- 排版、色彩与图形是否提高辨识度和可读性。
- 组件是否在不同页面保持一致。
- 视觉创意是否来自产品场景，而不是贴在界面外面的主题皮肤。

不要复制案例的完整构图、独特 Logo、吉祥物、品牌色组合、产品截图或核心插画。

## 四层映射

1. `来源线索`：物件结构、材质、操作痕迹、时间变化、空间关系或信息排序。
2. `设计原语`：线、角、轮廓、网格、标签、层叠、刻度、色块、纹理或动画方向。
3. `产品组件`：图标、容器、状态色、按钮、进度、列表、手势、导航、Widget 或转场。
4. `产品作用`：识别对象、显示进度、解释状态、引导动作、预防错误或支持恢复。

每个概念至少完成 3–5 条映射，并让主要原语在两种以上组件中复用。只出现一次且不影响理解的元素通常只是装饰。

## 十秒理解测试

生成前先写一个不超过四句的故事：

1. 用户原本在做什么？
2. 哪个具体问题发生了？
3. 用户在 App 里只做了什么？
4. 屏幕发生了什么可见变化，用户得到什么结果？

前两张图必须让不了解项目的人复述这四点中的前三点。若视觉先展示品牌哲学、材料推导或系统入口，而核心行为仍不清楚，应调整顺序。

## 图组叙事

建议 5–7 张独立图片：

- `problem`：真实场景和问题发生前后。
- `solution`：一句话方案，避免抽象口号。
- `core-screen`：只保留完成核心任务所需的信息。
- `state-change`：用前后状态、关键帧或明确数字变化展示动作结果。
- `outcome`：中断恢复、导出、回看或实际使用闭环。
- 可选 `onboarding`：最短首次使用流程。
- 可选 `system-or-scope`：系统入口、Widget、设计系统或 MVP 边界。

每一张都要有独立信息价值。手机模型、渐变、卡片和装饰线不能替代产品设计。
