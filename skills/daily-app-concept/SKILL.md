# Daily App Concept

完成一个经证据筛选、产品逻辑清楚、视觉能解释核心行为的移动 App 概念。研究清单、候选标题或绘图提示词不是完成状态；最终必须包含实际图片文件。

## 开始前

确定当天日期、输出目录和目标设备。默认输出到用户指定工作区的 `outputs/daily-app-concept/YYYY-MM-DD/`。如果存在历史索引，先读取全部条目并查看最近 7 期图片，避免重复需求、主体、核心交互和主视觉模板。

需要当前需求、产品数据或设计案例时浏览互联网，以原始页面为准。优先读取近 90 天材料，记录发布日期、访问日期、可见热度和证据边界。

## 工作流

### 1. 筛选真实需求

研究至少 3 个候选方向。每个候选都评估用户痛点、现有替代、行为成本、竞品覆盖和个人开发可行性。

正式选择的方向至少具备：

- 两条普通用户直接反馈，不能只用开发者推广帖。
- 一个已上线可比产品的市场证明，例如可独立查看的评分与评论量。
- 一个官方技术或平台来源，用来确认关键能力可实现。
- 一个从大类需求中收窄的切口，明确竞品已经覆盖什么、本方案为何仍值得验证。

分别标记 `需求证据`、`市场证明`、`创作者自述` 和 `仍是推断`。证据不足就换题。详细门槛与评分方法见 [需求证据与选题](references/evidence-and-selection.md)。

### 2. 定义窄产品

用一句话写清：

`谁，在什么时刻，通过什么核心动作，立即得到什么结果。`

同时定义 App 名、目标用户、触发时机、核心任务、核心一屏、3–5 个关键步骤、竞品边界、MVP、明确不做的内容、技术可行性、收费假设和主要风险。

优先无需账号、无需内容冷启动、无需长期人工运营、无需昂贵外部 API 的本地优先产品。若价值依赖持续拍照、分类、填写或维护，必须有用户反馈证明这种额外操作可接受，并写明留存风险。

### 3. 研究设计案例

先研究真实产品流程，再研究视觉表达。选择 3–6 个相关案例，记录作者、原始链接、访问日期、可借鉴的方法和许可判断。

只提炼层级、信息密度、状态反馈、排版、色彩、组件或动效逻辑。不得搬运、描摹或重新生成第三方独特 Logo、吉祥物、完整构图、界面截图或核心图形。来源渠道与判断方法见 [视觉研究与产品抽象](references/visual-system.md)。

### 4. 从产品行为抽象视觉

生成图片前列出 3–5 组映射：

`来源线索或操作痕迹 → 设计原语 → 界面组件或状态 → 承担的产品作用`

每个视觉元素都必须帮助识别、理解信息、区分状态或完成操作。无法说明作用的装饰应删除。

先通过“十秒理解测试”：一个不了解项目的人，只看前两张图，也能复述用户遇到的问题、核心动作和结果。若不能，先改叙事，不要继续堆风格。

### 5. 生成 App 概念图

默认使用图像生成能力逐张制作 5–7 张独立 PNG，并保持 App 名、设备、字体、色彩、图标、核心对象和组件一致。尺寸与比例由使用场景决定，但同组图片应统一。

图组至少覆盖这些叙事角色：

1. `problem`：具体用户场景和可见问题。
2. `solution`：一句话方案与主要结果。
3. `core-screen`：核心一屏的信息优先级与主操作。
4. `state-change`：操作前后发生了什么变化。
5. `outcome`：中断恢复、完成结果或真实场景闭环。

第 6、7 张可展示首次使用流程、Widget、系统入口、设计系统、MVP 边界或收费假设。产品未开发时，在图组中清楚标注“App concept”或“概念设计，尚未上线”。

生成后逐张检查文字、裁切、可读性、状态连续性、第三方标志和视觉漂移。核心行为不清楚时优先重做叙事图，不用说明文字为模糊界面兜底。

### 6. 保存与校验

输出目录遵循 [交付与校验](references/deliverables.md)，至少包含：

- `research.md`
- `concept.md`
- `visual-system.md`
- `manifest.json`
- `images/` 中的 5–7 张 PNG

运行：

```bash
python3 scripts/validate_output.py <输出目录> --json
```

校验通过后才能把 `manifest.json` 的状态写成 `complete`。完成状态只表示研究、产品定义和图片文件齐全，不代表产品已开发、发布或获得市场验证。

## 最终交付

直接给出选中需求、证据强弱、App 定义、MVP、收费假设、竞争风险、视觉推导和实际文件链接。说明图片数量、尺寸、唯一哈希与校验结果。不要生成社交平台标题、正文、标签、封面文案、上传顺序或发布包，除非用户另行要求。
